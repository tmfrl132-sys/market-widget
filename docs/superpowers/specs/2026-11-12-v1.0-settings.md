# 경제지표 위젯 v1.0 설계: 앱 설정 화면, 티커 추가, 잠수 차트 MDD, 큰 기본 크기

- 작성: 2026-11-12, widget-architect
- 기준 코드: 브랜치 `feature/v1.0-settings`(시작점 `main` 7091d8e = v0.9.0 배포본). 배포 중 APK는 `v0.9.0`(4,251,936바이트).
- 바탕 설계: `2026-10-30-market-widget-design.md`, `2026-11-06-v0.9-indicators.md`. 이 문서에 없는 내용은 그 설계를 따른다.
- 표기: **[실측]** 2026-11-12 23:00~23:30 서울에 직접 호출해 확인, **[미확인]** 확인하지 못해 구현·배포 뒤 확인할 항목.

## 1. 목적과 사용자가 정한 것

사용자 요청(2026-11-12)과 답변이다. 시안 선택 없이 이 문서의 추천안 하나로 확정한다.

1. 위젯에 보일 경제지표를 사용자가 고른다(켜기/끄기, 순서).
2. 위젯 기본 크기를 키운다(4×3 → 6×4). 손으로 늘리는 건 지금도 제한이 없다.
3. 티커를 추가하면 기존 지표와 같은 기준(시세, 오늘 차트, 1개월~MAX, 고점 대비, MDD, 장 상태, 큰 움직임)으로 그린다.
4. 지표 선택과 티커 추가는 위젯이 아니라 **앱 설정 화면**에서 한다.
5. 티커는 이름·코드로 검색한다. `삼성전자`, `AAPL`처럼 입력하면 후보가 나오고 눌러서 추가한다. 대상은 한국 주식, 미국 주식, ETF, 지수다.
6. MDD는 **잠수 차트 + 구간 표시**로 다시 그린다. 아래 낙폭 차트를 0% 위, 아래로 채운 면적으로 그리고 모든 기간에서 보여 준다. 위 가격 차트에는 최대 낙폭 구간(고점→바닥→회복)을 옅게 칠하고 고점·바닥 점을 찍는다. 위아래 시점을 정확히 맞춘다.

지키는 과거 결정: 한국식 색(상승 빨강, 하락 파랑), 태블릿에 인증키 없음, 출처 하나가 실패해도 나머지 갱신, 코스피·코스닥 네이버 우선, Yahoo `previousClose` 미사용, 전체 기간은 `period1=0` 일봉, 비용 0원.

## 2. 성공 기준 (태블릿에서 확인)

1. 런처의 "경제지표" 아이콘이나 위젯 머리줄의 **설정** 버튼을 누르면 설정 화면이 열린다.
2. 설정 화면에서 VIX를 끄면 1~2초 안에 위젯에서 VIX 타일이 사라진다. 다시 켜면 돌아온다.
3. ▲▼로 S&P500을 맨 위로 올리면 위젯 첫 타일이 S&P500이 되고, 자동모드도 그 순서로 돈다.
4. 검색 칸에 `삼성전자`를 넣으면 첫 후보가 `삼성전자 · 005930 · 코스피`다. `AAPL`을 넣으면 `Apple Inc.`(또는 `애플`)이 나온다.
5. 삼성전자를 추가하면 1분 안에 위젯에 삼성전자 타일이 생기고 값·등락률·작은 차트가 나온다. 평일 장중에는 초록 점이 보이고 값이 네이버 화면과 1분 안쪽으로 같다.
6. 삼성전자 타일을 누르면 오늘·1개월·3개월·1년·5년·MAX 차트가 모두 나오고, MAX에 `1999년~`처럼 시작 연도와 고점 대비·MDD가 나온다.
7. 코스피 1년 차트에서 가격 차트 아래에 잠수 차트가 붙고, 두 차트의 같은 날짜가 세로로 정확히 같은 위치에 있다(세로 보조선이 위아래로 이어진다).
8. 가격 차트에 최대 낙폭 구간이 옅은 파란색으로 칠해지고 고점(흰 점)·바닥(파란 점)이 보인다. 회복하지 못했으면 칠이 오른쪽 끝까지 이어진다.
9. 원/달러, 달러인덱스, 미 10년물, VIX는 잠수 차트·구간 칠·MDD 줄이 없다(지금과 같음).
10. 새로 놓은 위젯은 6×4 크기로 놓인다. 이미 놓인 위젯은 크기가 그대로다.
11. 추가 티커가 8개이면 9번째 **추가** 버튼이 눌리지 않고 `최대 8개까지 추가할 수 있습니다`가 보인다.

## 3. 화면과 동작

### 3.1 앱 설정 화면

**결정: `MainActivity`를 Jetpack Compose(Material3) 설정 화면으로 바꾼다.**
이유: 켜기 스위치, 검색 칸, 목록, 대화상자를 화면 코드 몇 줄로 만들 수 있고, 이미 Compose 컴파일러 플러그인(`org.jetbrains.kotlin.plugin.compose` 2.0.21)이 있어 빌드 설정을 크게 바꾸지 않는다.

- 추가 의존성(`android/app/build.gradle.kts`):
  ```kotlin
  implementation(platform("androidx.compose:compose-bom:2024.12.01"))
  implementation("androidx.activity:activity-compose:1.9.3")
  implementation("androidx.compose.material3:material3")
  implementation("androidx.compose.ui:ui")
  ```
  `material-icons-extended`는 넣지 않는다. 이유: 수 MB짜리라 APK가 크게 는다. 아이콘 대신 `▲`, `▼`, `삭제` 글자 버튼을 쓴다.
- APK 크기: 지금 4.25MB. R8(코드 줄이기)을 끈 상태 그대로라 **약 10~12MB로 늘 것으로 추정**한다 [미확인, CI 빌드에서 실측]. 15MB를 넘으면 리더에게 보고한다. R8을 켜지 않는 이유: Glance `ActionCallback`과 kotlinx 직렬화가 클래스 이름·반사를 써서, 규칙이 하나만 빠져도 위젯 버튼이 조용히 죽는다. 태블릿 한 대에 직접 설치하는 앱이라 크기보다 안정성이 중요하다.
- Compose BOM이 Glance가 쓰는 Compose runtime 버전을 1.7.x로 올린다. Glance 1.1.1과 함께 쓰는 데 문제가 알려진 바는 없다 [미확인, CI 빌드로 확인].
- 액티비티는 `android.app.Activity` → `androidx.activity.ComponentActivity`. 매니페스트 액티비티 테마는 `@android:style/Theme.DeviceDefault.NoActionBar`. 안드로이드 15의 화면 끝까지 그리기에 맞춰 `Scaffold`와 `WindowInsets.safeDrawing` 여백을 쓴다(지금 `fitsSystemWindows`와 같은 목적).
- 색은 위젯과 같은 어두운 색(`BACKGROUND #111827`, `TILE #1B2433`, 글자 `#F3F4F6`/`#8B95A7`, 켜짐 `#4D8DFF`)을 `darkColorScheme`에 넣는다. 이유: 위젯과 같은 앱으로 보이게 한다.
- 상태 관리는 ViewModel 라이브러리 없이 화면 상태 클래스(`mutableStateOf`)와 `rememberCoroutineScope`로 한다. 이유: 화면이 하나뿐이고 의존성을 늘리지 않는다.

**화면 구성**

태블릿 가로(화면 폭 840dp 이상)는 왼쪽 "위젯에 보일 지표", 오른쪽 "종목 추가" 두 칸이다. 좁으면 위아래 한 칸으로 쌓는다. 이유: 태블릿 가로 화면에서 목록과 검색을 동시에 보면서 추가 결과를 바로 확인할 수 있다.

```
경제지표 설정
┌ 위젯에 보일 지표  켜짐 14 / 15       [기본값으로] ┐  ┌ 종목 추가  3 / 최대 8                 ┐
│ ▲ ▼  코스피        KS11 · 기본            (●) │  │ [ 이름이나 코드 (예: 삼성전자, AAPL) ][검색] │
│ ▲ ▼  코스닥        KQ11 · 기본            (●) │  │ 삼성전자   005930 · 코스피          [추가]   │
│ ...                                           │  │ KODEX 삼성전자채권혼합 448330 · 코스피 [추가] │
│ ▲ ▼  VIX           VIX · 기본             ( ) │  │ ...                                         │
│ ▲ ▼  삼성전자      005930.KS · 23:05 받음  (●) [삭제] │  │                                     │
└───────────────────────────────────────────────┘  └─────────────────────────────────────────────┘
                                   [홈 화면에 위젯 추가]
```

- **지표 목록**: 기본 13개와 추가 티커가 지금 위젯 순서대로 한 목록에 있다. 줄마다 ▲·▼(한 칸 이동), 이름, 작은 글자(기본 지표는 `id · 기본`, 추가 티커는 `심볼 · 상태`), 켜기 스위치. 추가 티커에는 **삭제** 버튼이 더 있다.
  - 순서는 ▲▼ 버튼으로 바꾼다. 이유: 끌어서 옮기기는 Compose 기본 기능이 아니라 별도 코드가 많이 들고 손이 미끄러지면 순서가 엉킨다. 버튼은 한 번에 한 칸이라 확실하다. 맨 위 ▲, 맨 아래 ▼는 흐리게 막는다.
  - 켜진 지표가 1개면 그 스위치를 끌 수 없고 `최소 1개는 켜 두어야 합니다`가 보인다. 이유: 0개면 위젯이 빈 칸이 된다.
  - 추가 티커 상태 글자: `받는 중`(아직 데이터 없음), `HH:mm 받음`(마지막 시세 성공 시각), `받지 못함 · 다시 시도 중`(마지막 시도 실패).
  - **삭제**는 `삼성전자를 지울까요?` 확인 대화상자 뒤 지운다.
  - **기본값으로**: 순서를 기본(기본 13개 수집기 순서 → 추가 티커 추가 순서)으로, 모두 켜짐으로 되돌린다. 추가 티커는 지우지 않는다. 확인 대화상자를 띄운다.
- **종목 추가**: 검색 칸 + **검색** 버튼. 글자를 입력하고 0.4초 멈추면 자동으로도 검색한다(2글자 이상, 숫자·영문은 1글자 이상). 결과 줄은 이름, `코드 · 시장`(예: `005930 · 코스피`, `AAPL · 나스닥`, `^N225 · 지수`, `ETH-USD · 암호화폐`), **추가** 버튼. 이미 있는 종목(기본 지표 심볼 포함)은 `추가됨`, 8개가 차면 버튼이 막히고 위에 `최대 8개까지 추가할 수 있습니다`.
  - **추가**를 누르면 버튼이 `확인 중`이 되고 3.2절 확인 요청을 보낸다. 성공하면 목록 맨 아래에 켜진 상태로 붙고 `삼성전자를 추가했습니다. 위젯에 곧 나타납니다`(아래쪽 알림 줄). 실패하면 `이 종목은 시세를 받을 수 없습니다`.
- **홈 화면에 위젯 추가** 버튼: 지금 `MainActivity`의 기능(`requestPinAppWidget`)을 그대로 옮긴다. 지원하지 않는 홈 화면이면 지금 안내 문구를 띄운다.

**저장 방식**

**결정: 앱 내부 폴더의 `settings.json` 파일 하나에 kotlinx 직렬화로 저장한다. DataStore는 쓰지 않는다.**
이유: 위젯은 그릴 때마다 `data.json` 캐시를 동기로 읽는데(`Repository.cached()`), 설정도 같은 방식이면 Glance 화면 코드에서 바로 읽을 수 있다. DataStore는 비동기 흐름이라 위젯 그리기 안에서 읽기가 번거롭고, 순서 있는 목록과 티커 정보를 담기에는 JSON이 더 단순하다. 쓰다 만 파일을 읽지 않게 지금 캐시처럼 임시 파일에 쓴 뒤 한 번에 바꿔치기한다.

```json
{
  "version": 1,
  "order": ["GSPC", "KS11", "T:005930.KS"],
  "hidden": ["VIX"],
  "custom": [
    {"id": "T:005930.KS", "symbol": "005930.KS", "name": "삼성전자", "kind": "EQUITY", "naver_code": "005930"}
  ]
}
```

- 파일이 없거나 읽을 수 없으면 기본값(빈 `order`, 빈 `hidden`, 빈 `custom`) = 기본 13개 모두 켜짐, 수집기 순서. 이유: 처음 설치와 v0.9.0에서 올라온 경우가 같은 화면이다.
- 추가 티커 id는 `T:` + Yahoo 심볼. 이유: 기본 지표 id(`KS11` 등)와 겹치지 않고, 위젯 상태(`selected`, `compare`)에 그대로 쓸 수 있다.
- `kind`는 `EQUITY`, `ETF`, `INDEX`, `CRYPTOCURRENCY` 중 하나로, 추가할 때 Yahoo 확인 응답의 `meta.instrumentType`에서 정한다.
- `naver_code`는 한국 주식·ETF(`.KS`, `.KQ`)만 6자리 코드, 나머지는 `null`.
- 실제 보일 목록은 순수 함수 `visibleQuotes`(6.4절)로 정한다. `order`에 없는 지표(앞으로 수집기에 새로 생긴 기본 지표, 막 추가한 티커)는 맨 뒤에 붙고 켜진 상태다. 이유: 기본값이 "모두 켜짐"이고, 수집기에 지표가 늘어도 APK를 다시 깔 필요가 없게 한다.

**위젯 반영 시점**

- 켜기/끄기, 순서, 삭제, 기본값으로: 바뀔 때마다 바로 저장하고 `redrawAllWidgets(context)`를 부른다. 1~2초 안에 위젯이 다시 그려진다. 네트워크는 쓰지 않는다. 저장 버튼은 없다. 이유: 초보 사용자가 저장을 잊는 일을 없앤다.
- 추가, 그리고 꺼 둔 추가 티커를 다시 켤 때: 저장 → 다시 그리기(타일이 `-` 값으로 바로 생김) → `RefreshWorker.runOnce(context)`. 작업이 그 티커의 기록(1년·5년·MAX)을 받고 다시 그린다. 보통 5~30초 [추정, MAX 응답이 최대 334KB(gzip)].

**위젯에서 앱으로 가는 길**

- 위젯 머리줄 **자동**과 **⟳** 사이에 `설정` 글자 버튼(자동 버튼과 같은 모양)을 둔다. 누르면 `actionStartActivity<MainActivity>()`로 설정 화면이 열린다. 머리줄 자식 수는 7개로 Glance 한도(10개) 안이다.
  이유: 톱니 기호(⚙)는 기기에 따라 컬러 이모지로 그려져 어두운 위젯에서 튀고, 초보 사용자에게 글자가 더 분명하다.
- 런처 아이콘도 같은 화면을 연다.

### 3.2 티커 검색

**실측 결과**

| 경로 | `삼성전자` | `AAPL` | `005930` | `kakao` | `nikkei` | `ETH` |
| --- | --- | --- | --- | --- | --- | --- |
| Yahoo `query2.finance.yahoo.com/v1/finance/search` | **HTTP 400 `Invalid Search Query`** | AAPL 1위 | 005930.KS 1위 | 035720.KS 등 | ^N225 1위 | ETH-USD 1위 |
| 네이버 `ac.stock.naver.com/ac` | 005930 삼성전자 KOSPI 1위 | AAPL `애플` NASDAQ | 005930 삼성전자 | - | `니케이` → N225 WORLD_INDEX | `이더리움` → 결과 없음 |

- Yahoo 검색은 **한글을 받지 않는다**(400). 영문 `samsung`은 005930.KS를 찾지만 이름이 `SamsungElec`이다.
- 네이버 자동완성은 한글 이름, 6자리 코드, 미국 티커(`AAPL`, `QQQ`)를 모두 찾고 이름이 한글이다(`애플`). 암호화폐는 없다.
- 응답 크기: 네이버 약 2.3KB(gzip 0.4KB), Yahoo 약 2KB.

**결정: 한글이 있으면 네이버만, 없으면 네이버와 Yahoo를 동시에 불러 합친다. 네이버 결과를 먼저 둔다.**
이유: 한글 이름을 찾는 길은 네이버뿐이고, 같은 종목이면 한글 이름이 위젯 타일에서 읽기 쉽다. Yahoo는 암호화폐와 영문 지수 검색을 채운다.

- 네이버: `https://ac.stock.naver.com/ac?q={검색어}&target=stock,ipo,index,marketindicator` [실측 200].
- Yahoo: `https://query2.finance.yahoo.com/v1/finance/search?q={검색어}&quotesCount=10&newsCount=0&listsCount=0&enableFuzzyQuery=false` [실측 200].
- 두 요청 모두 `User-Agent: Mozilla/5.0`(지금 `httpGet`과 같음), 제한 시간 10초.

### 3.3 위젯 배치

**결정: 타일 배치는 v0.9 식을 그대로 쓰고, 지표가 4개 이하일 때만 한 줄 칸 수를 4로 고정한다. 추가 티커는 최대 8개, 그래서 타일은 최대 21개다.**

```
최대 칸 수 = clamp(floor((W - 20) / 96), 4, 7)       (지금과 같음)
줄 수     = ceil(n / 최대 칸 수)                        (지금과 같음)
한 줄 칸 수 = max(ceil(n / 줄 수), 4)                    (바뀜: 4 미만 금지)
```

- 4 미만 금지 이유: 지금 식은 1개만 켜면 타일 하나가 1,200dp로 늘어나 글자가 왼쪽 구석에 몰린다. 4칸으로 고정하고 나머지는 빈 칸(지금처럼 `Spacer`)으로 채워 타일 폭이 늘 비슷하다.
- 최대 8개 이유: 기본 13개 + 8 = 21 = 7칸 × 3줄이라 넓은 위젯(폭 692dp 이상)에서 3줄을 넘지 않는다. 갱신마다 요청이 16회 늘어나는데(4.3절) 그 이상은 Yahoo 요청 제한 위험이 커진다.

| 폭 W | n=1 | n=3 | n=5 | n=8 | n=13 | n=15 | n=21 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1300dp | 4×1 | 4×1 | 5×1 | 4×2 | 7×2 | 5×3 | 7×3 |
| 500dp | 4×1 | 4×1 | 5×1 | 4×2 | 5×3 | 5×3 | 5×5 |
| 400dp | 4×1 | 4×1 | 4×2 | 4×2 | 4×4 | 4×4 | 4×6 |

(표기: 한 줄 칸 수 × 줄 수. 높이 계산 `topPartHeightDp(줄 수)`는 지금과 같다.)

**작은 차트 비트맵 픽셀 상한**: 타일이 21개면 작은 차트 비트맵이 지금보다 많아 위젯 전송 크기(약 1MB)를 넘을 수 있다. 작은 차트 전체를 160,000픽셀(RGB_565, 약 320KB)로 묶고 한 개당 `fitBitmap(w, h, 160_000 / n)`으로 줄인다. 큰 차트 250,000픽셀(약 500KB)과 합쳐 약 820KB다. 13개일 때는 지금 크기(한 개 약 11,400픽셀 × 13 = 148,000)가 상한 안이라 화면이 바뀌지 않는다.

**자동모드·비교·선택이 꺼진 지표를 가리킬 때**

모든 상태는 "지금 보이는 지표 id 목록"으로 정리한 뒤 쓴다. 순수 함수 `sanitizeSelection(selection, visibleIds)`(6.4절).

| 상태 | 가리키는 지표가 꺼짐/삭제됨 | 결과 | 이유 |
| --- | --- | --- | --- |
| `selected` | 예 | 선택 없음(발표 일정), 비교·고르는 중도 지움 | 안 보이는 타일의 차트를 열어 두면 닫을 타일이 없다 |
| `compare` | 예 | 비교만 지움, 주 지표 차트는 유지 | 주 지표는 여전히 보인다 |
| `compare_picking` | `selected`가 꺼짐 | 지움 | 위와 같음 |
| 자동모드 순환 | - | `autoQuoteIds`에 보이는 지표만 넘긴다. 현재 지표가 목록에 없으면 `nextAutoQuote`가 처음부터 돈다(지금 동작) | |

### 3.4 MDD: 잠수 차트와 최대 낙폭 구간

**현재 문제(코드 확인)**

- 낙폭 차트가 MAX에서만 나온다(`MarketWidget.kt:527`).
- 낙폭 점은 수집기가 묶음마다 최솟값 1개로 줄인 `max_drawdowns`(`collector/quotes.py:164`)라 가격 점(`max_closes`, 묶음마다 최저·최고 2개)과 개수가 다르다. 코스피 494점 대 246점(v0.9 data.json). 같은 x 비율로 늘려 그리므로 시점이 어긋난다(`XAxis.kt:152` 주석).
- 두 차트의 오른쪽 숫자 칸 너비가 각자 글자 길이로 정해지고(`ChartBitmap.kt:69`), 두 비트맵의 픽셀 상한이 달라 줄이는 비율도 다르다(`MarketWidget.kt:539`, `:602`). 그래서 그림 영역 폭이 달라진다(QA D5).

**결정: 잠수 차트의 점은 가격 차트와 같은 점(1:1)으로 만들고, 두 비트맵은 같은 축척·같은 오른쪽 숫자 칸 폭으로 그린다.**
이유: 점 개수와 그림 영역 폭이 같으면 같은 인덱스가 같은 x 좌표에 놓여 시점이 정확히 맞는다. 세로 보조선(`xTicks`)도 같은 위치에 그려져 눈으로 확인할 수 있다.

**기간별 낙폭 계산 근거**

| 기간 | 가격 점 | 낙폭 점(1:1) | 고점 기준 | MDD 숫자 | 구간(고점·바닥·회복) |
| --- | --- | --- | --- | --- | --- |
| 오늘 | 5분봉 | 없음 | - | 없음(지금과 같음) | 없음 |
| 1개월·3개월·1년 | `daily` 끝 22/63/전체 | 기기가 그 점으로 계산 | 기간 첫 값부터의 누적 고점 | 그 점의 최솟값(지금 `drawdownSummary`와 같음) | 기기가 그 점으로 계산 |
| 5년 | `weekly` 주봉 | 기기가 주봉으로 계산 | 같음 | 주봉 종가 기준. 일봉 MDD보다 얕을 수 있다(주 중 바닥이 빠짐) | 같음 |
| MAX | `max_closes` (줄인 점) | **수집기가 보내는 `max_depths`** | 전체 일봉 누적 고점 | 수집기 `mdd`(전체 일봉, 지금과 같음) | 수집기 `mdd_peak_date`·`mdd_trough_date`·`mdd_recovery_date` |

- 오늘 제외 이유: 몇 시간짜리 5분봉의 낙폭은 등락률과 거의 같고, 지금도 오늘은 고점 대비·MDD 줄을 숨긴다. 사용자 결정의 "모든 기간"은 지금 MAX만 있는 낙폭 차트를 1개월~5년에도 보이게 하는 뜻으로 해석했다.
- 1개월~5년 고점 기준 이유: 지금 화면의 "고점 대비"·"MDD"가 기간 기준이고, 기간 잠수 차트는 기간 시작에서 0%로 출발하는 것이 관례다(PortfoliosLab 기간 선택 방식).
- **MAX를 수집기 값으로 맞추는 이유 [실측]**: 줄인 점만으로 누적 고점을 다시 계산하면 MDD 숫자 자체는 같지만(코스피 -64.7, S&P500 -56.8, 비트코인 -83.4, 삼성전자 -64.8, AAPL -82.2, 금 -44.4 모두 일치, 바닥 점이 남아 있음), **중간 점의 낙폭은 최대 3.4~11.4%p 얕게** 나온다(AAPL 11.4%p, 비트코인 6.8%p). 같은 묶음 안에서 바닥 뒤에 새 고점이 나오면 바닥 앞의 고점이 점에서 빠지기 때문이다. 그래서 수집기가 전체 일봉으로 계산한 낙폭을 남긴 점 위치마다 보낸다(`max_depths`).
- **줄인 점에서 생기는 오차를 없애는 방법**: 수집기는 MDD 고점·바닥·회복 위치와 사건 최저점 위치를 남길 점에 반드시 넣는다(6.2절). 그래서 잠수 차트의 최저점이 정확히 `mdd`이고, 구간 칠의 양 끝과 사건 점이 실제 날짜에 놓인다. 점은 최대 7개 늘어난다(500 → 최대 507).
- 옛 data.json·옛 캐시(`max_depths` 없음)를 받으면 MAX 낙폭을 `max_closes`로 기기가 계산한다(위 오차가 있는 대체 경로). 구간 날짜가 없으면 구간도 `max_closes`로 계산한다.

**잠수 차트 그리기**

- 값: 낙폭 %(0 이하). 맨 위가 0%이고 아래로 내려간다.
- 선: `DOWN`(#4D8DFF) 2.5dp. 면적: 선과 0% 사이를 `DOWN` 알파 0x55로 **고르게** 칠한다(그라데이션 없음). 이유: 관례적인 잠수 차트 모양이고, 깊이가 면적으로 바로 읽힌다.
- 0% 선: 기준 점선(지금 `drawBaseline`) 문구 없이. 오른쪽 숫자는 `formatAxisPct`(`-20%`).
- 표시(`marks`, 지금 사건 표시와 같은 방식, 겹치면 위로 올림):
  - 바닥: `MDD -34.2%`. 사건과 같은 점이면 `외환위기 -64.7% · MDD` 하나로 합친다.
  - 현재(마지막 점): `현재 -5.1%`. 바닥이 마지막 점이면 `MDD·현재 -34.2%` 하나.
  - 사건(MAX만): `max_events[].date`가 있는 사건만, 날짜 이하 마지막 점에 `닷컴버블 -77.9%`. 날짜가 없는 옛 데이터의 사건은 그리지 않는다. 이유: 옛 `index`는 `max_drawdowns` 묶음 위치라 새 점과 맞지 않는다.
- 구간 칠: 가격 차트와 같은 범위를 같은 색으로 옅게 칠한다(아래 참조). 위아래가 맞는지 눈으로 확인하기 쉽다.

**가격 차트 위 최대 낙폭 구간**

- 구간 = 고점 점 ~ 회복 점(회복하지 못했으면 마지막 점). 그림 영역 전체 높이를 `DOWN` 알파 0x1F(약 12%)로 칠한다. 칠은 영역 채우기·선보다 먼저 그린다.
- 점: 고점은 `TEXT`(#F3F4F6) 원, 바닥은 `DOWN` 원. 반지름 `strokePx × 2`, 바깥에 배경색 테두리. 마지막 값 점(지금 `drawEndDot`)은 그대로.
- 가격 차트에는 글자를 더하지 않는다. 이유: 가격 차트에는 이미 기준 점선 문구와 세로축 숫자가 있어 붐빈다. 날짜와 깊이는 문구 줄과 잠수 차트에 있다.
- 로그 눈금에서도 점 인덱스로 칠하므로 그대로 맞는다.

**문구 줄(지금 `고점 대비 · MDD` 줄)**

```
고점 대비 -5.1%  ·  MDD -34.2%  ·  7/10 고점 → 8/5 바닥 → 11/3 회복
고점 대비 -12.0%  ·  MDD -34.2%  ·  24.7.10 고점 → 24.8.5 바닥 → 미회복
```

- 날짜 형식: 1개월·3개월 `M/d`, 1년 `yy.M.d`, 5년·MAX `yyyy.M`. 날짜를 믿을 수 없으면(`chartDates`가 빔) 구간 부분을 뺀다. MDD가 0이면(계속 올랐음) `MDD 0.0%`까지만.
- 글자 11sp 굵게(지금과 같음), 한 줄로 자른다.

**두 차트의 시점 맞추기(구현 규칙)**

1. 픽셀 줄이기는 두 그림을 합친 크기로 한 번 한다: `fitBitmap(fullW, priceH + underwaterH, MAX_CHART_PIXELS)`. 두 비트맵이 같은 폭(px), 같은 글자 크기, 같은 선 굵기를 쓴다.
2. 두 차트의 세로축(가격 `fixedAxis` 또는 `yAxisFor(값 + 기준값)`, 잠수 `yAxisFor(낙폭 + 0)`)을 먼저 구하고, 두 축 숫자 중 가장 긴 글자로 오른쪽 숫자 칸 폭 하나를 정해 `renderLine`에 함께 넘긴다(새 인자 `gutterPx`).
3. 점 개수가 같고(1:1) 가로 위치는 지금처럼 인덱스 균등 배치라 같은 인덱스가 같은 x다.
4. 가로축 글자는 아래 잠수 차트에만, 가격 차트에는 세로 보조선만(지금 MAX 규칙을 모든 기간으로).

**낙폭 없는 지표와 추가 티커**

- 원/달러, 달러인덱스, 미 10년물, VIX: 지금처럼 수집기가 `mdd=null`을 보내므로 잠수 차트, 구간, 문구 줄이 모두 없다. 이유: 환율·금리·변동성은 고점 대비 하락이 손실이 아니다.
- 추가 티커: 주식, ETF, 지수, 암호화폐 모두 낙폭을 계산한다. 단 아래 지수 심볼은 낙폭을 계산하지 않는다(`mdd=null`): `^VIX`, `^VXN`, `^VVIX`, `^TNX`, `^TYX`, `^FVX`, `^IRX`. 이유: 기본 지표의 `NO_DRAWDOWN`과 같은 뜻(변동성·금리).

**비교 모드와의 관계**: 비교 중에는 잠수 차트, 구간 칠, 고점·바닥 점, 문구 줄을 모두 숨긴다(지금과 같음). 이유: 두 선 중 어느 지표의 낙폭인지 헷갈린다.

**화면 높이 배분**

```
그림 높이   = max(40dp, 차트 칸 높이 - 100dp)          (낙폭 줄 있을 때, 지금과 같음)
잠수 차트 표시 = 낙폭 있음 && 기간 ≠ 오늘 && 비교 아님 && 그림 높이 ≥ 140dp
잠수 차트 높이 = 그림 높이 × 0.35
가격 차트 높이 = 그림 높이 - 잠수 차트 높이
```

- 0.35 이유: 지금 MAX 0.4보다 조금 줄여 가격 차트를 우선한다. 140dp에서 잠수 49dp·가격 91dp.
- 140dp 미만이면 잠수 차트 없이 가격 차트에 구간 칠과 점만 그린다. 문구 줄은 남는다.
- 예: 위젯 높이 560dp, 타일 2줄 → 차트 칸 330dp → 그림 230dp → 가격 150dp, 잠수 80dp.

### 3.5 위젯 기본 크기

**결정**

```xml
android:minWidth="480dp"
android:minHeight="300dp"
android:minResizeWidth="250dp"
android:minResizeHeight="110dp"
android:targetCellWidth="6"
android:targetCellHeight="4"
```

- `targetCellWidth/Height` 6×4: 사용자 예시 그대로다. 안드로이드 12 이상 홈 화면은 이 칸 수로 처음 놓는다. 갤럭시 탭 가로 홈 화면은 보통 6칸 이상이라 가로 전체에 가깝게 놓인다 [미확인, 사용자 태블릿의 칸 수를 모름]. 칸이 6개보다 적으면 홈 화면이 줄이거나 `minWidth` 크기로 놓는다 [미확인].
- `minWidth/minHeight` 480×300dp: 안드로이드 11 이하나 칸 수를 쓰지 않는 홈 화면의 기본 크기다. 폭 480dp는 한 줄 4칸(13개면 4줄), 높이 300dp는 타일만 보이는 크기다. 너무 크게 잡으면 칸 수가 적은 홈 화면에서 놓이지 않을 수 있어 중간 값으로 둔다.
- `minResizeWidth/Height` 250×110dp: 지금 최소 크기(지금은 `minWidth/minHeight`가 최소 크기 역할)를 그대로 지킨다. 이유: 이것을 넣지 않으면 `minWidth`를 키운 만큼 사용자가 위젯을 작게 줄일 수 없게 된다.
- **이미 놓인 위젯**: 크기가 바뀌지 않는다. 이 설정은 새로 놓을 때만 쓰인다. 사용자 보고에 "새 크기를 쓰려면 위젯을 길게 눌러 늘리거나, 설정 화면의 **홈 화면에 위젯 추가**로 새로 놓고 옛 위젯을 지우세요"를 적는다. 새로 놓으면 위젯별 상태(기간, 선택, 로그, 자동)는 처음 값이다.

### 4.2 추가 티커: 기기가 직접 받는다

수집기는 사용자 목록을 모른다(설정은 태블릿에만 있다). 그래서 추가 티커의 모든 값은 기기가 Yahoo·네이버에서 받아, 수집기와 같은 규칙의 Kotlin 순수 함수(6절)로 `Quote`를 만든다. 결과는 `custom.json` 캐시에 따로 저장한다. 위젯은 `data.json` 캐시의 기본 지표와 `custom.json`의 추가 티커를 `visibleQuotes`로 합쳐 그린다.

| 받는 것 | 주소 | 언제 | 이유 |
| --- | --- | --- | --- |
| 시세(전일 종가 포함) | `range=5d&interval=1d` (지금 `YAHOO_URL`) | 갱신마다(30분 작업, 화면 켜짐 5분) | 기본 지표와 같다 |
| 오늘 5분봉·장 시간 | `range=1d&interval=5m` (지금 `INTRADAY_URL`) | 갱신마다 | 같다 |
| 1년 일봉 | `range=1y&interval=1d` | 마지막 성공이 6시간보다 오래됐거나 없을 때 | 사이에는 시세로 끝 값만 고친다(지금 `applyLiveQuotes`). 기기가 하루 넘게 꺼져 있다 켜져도 6시간 규칙으로 바로 다시 받아 빠진 날이 없다 |
| 5년 주봉 | `range=5y&interval=1wk` | 1년 일봉과 함께 | 같다 |
| 전체 기간 일봉 | `period1=0&period2={지금}&interval=1d` (수집기 `MAX_URL`과 같음) | 추가할 때, 그 뒤 7일마다, 비어 있을 때 | 최대 1.3MB(AAPL, gzip 334KB)라 자주 받지 않는다. 사이에는 끝 값·고점·MDD·`max_depths` 끝을 시세로 고친다 |

- 꺼 둔 추가 티커는 받지 않는다. 다시 켜면 바로 받는다(3.1절).
- 동시에 최대 4개 티커를 받는다. 이유: 한 번에 수십 요청을 보내 Yahoo가 막는 일을 줄인다. 기본 13개는 지금처럼 따로 동시에 받는다.
- 안드로이드 `HttpURLConnection`은 gzip 압축을 스스로 요청하고 풀어 준다. 그래서 데이터량은 gzip 크기로 잡는다.

**한국 개별 주식·ETF: 네이버 실시간 경로 [실측]**

Yahoo의 한국 주식은 지수처럼 약 20분 늦다(Yahoo 공지, 지수 실측 20~25분). 그래서 장중에는 네이버를 쓴다. 다만 네이버 종목 값에는 **넥스트레이드(NXT) 시간외 거래가 섞인다**:
- 2026-11-12 20:20 서울, 삼성전자 `m.stock.naver.com/api/stock/005930/basic`의 `closePrice`는 206,500(NXT 애프터마켓 20:00 값)이었고, KRX 종가는 208,000(Yahoo 일봉, 네이버 1분봉 15:30 값)이었다.
- 네이버 1분봉 `api.stock.naver.com/chart/domestic/item/005930/minute`은 09:00~19:59까지 있다(NXT 포함).
- 네이버 일봉도 NXT 마지막 값이다(11-12 206,500, 11-11 208,000). Yahoo 일봉(11-12 208,000, 11-11 206,000)과 다르다.
- `compareToPreviousClosePrice`는 부호가 있고(`-150`, `-36,000`) KRX 전일 종가 기준이다(206,500 − 500 = 206,000 = 네이버 `전일 206,000`).

**결정: 서울 평일 09:00~16:00에만 네이버를 쓰고, 값은 KRX 정규장(09:00~15:30) 1분봉에서 만든다. 그 밖의 시간과 실패 시에는 Yahoo를 쓴다.**
이유: 1분봉의 15:30까지 값은 KRX 체결이라 Yahoo 일봉(KRX 공식 종가)과 이어진다. `closePrice` 대신 1분봉 끝 값을 쓰면 장 마감 뒤 NXT 값이 섞이지 않는다. 16:00이면 Yahoo에도 15:30 종가가 들어와 있다.

순수 함수 `naverStockQuote(basicText, minuteText, nowSeoul)`:

```
1. nowSeoul이 토·일이거나 09:00 이전 또는 16:00 이후면 null (Yahoo로)
2. 1분봉 중 마지막 날짜의 봉만, 그중 시각이 09:00:00~15:30:59인 봉만 남긴다
3. 남은 봉이 없거나 그 날짜가 nowSeoul 날짜가 아니면 null
4. price = 남은 마지막 봉 값
5. prevClose = basic.closePrice - basic.compareToPreviousClosePrice   (둘 중 하나라도 못 읽으면 null)
6. change = round2(price - prevClose), changePct = round2(change / prevClose × 100)
7. 오늘 봉 = 남은 봉을 5개마다 1개(마지막 봉은 지킴) — 지금 parseNaverMinutes와 같은 줄이기
   장 시간 = 그 날짜 09:00 ~ 15:30 (서울)
```

- 고정 기대값: 위 실측 값으로 `nowSeoul = 2026-11-12 15:45`, basic `closePrice "206,500"`, `compareToPreviousClosePrice "500"`, 1분봉 15:30 값 208000 → `price 208000.0`, `prevClose 206000.0`, `change 2000.0`, `changePct 0.97`. 같은 자료로 `nowSeoul = 20:20`이면 null.
- 장중 `basic.closePrice`가 KRX 값인지 NXT 값인지 확인하지 못했다 [미확인]. 위 규칙은 장중에도 1분봉 끝 값을 쓰므로 `closePrice`는 전일 종가를 거꾸로 구하는 데만 쓴다. 장중 `compareToPreviousClosePrice`가 KRX 전일 종가 기준인지 [미확인, 평일 장중 확인].
- 기본 코스피·코스닥 지수의 네이버 경로는 바꾸지 않는다(지수는 NXT가 없다).
- ETF 1분봉도 같은 주소로 받아진다 [실측 069500, 0162Z0 200].

## 5. data.json 계약 변경

| 필드 | 위치 | 형식·단위 | 빈 값 | 만드는 곳 | 읽는 곳 | 옛 APK 영향 |
| --- | --- | --- | --- | --- | --- | --- |
| `max_depths` | Quote | `List<Double>`, 고점 대비 낙폭 %, 0 이하, 소수 첫째 자리. `max_closes`와 1:1. 전체 일봉 누적 고점 기준 | `[]` (낙폭 없는 지표, 첫 수집 실패) | 수집기(기본), 기기(추가 티커) | 위젯 MAX 잠수 차트 | 없음(모르는 필드 무시) |
| `mdd_peak_date` | Quote | `String?`, `YYYY-MM-DD`, MDD 직전 고점 날짜. `max_dates` 안에 있다 | `null` (낙폭 없음, MDD 0) | 같음 | 위젯 MAX 구간 | 없음 |
| `mdd_trough_date` | Quote | `String?`, MDD 바닥 날짜. `max_dates` 안에 있다 | `null` | 같음 | 같음 | 없음 |
| `mdd_recovery_date` | Quote | `String?`, 바닥 뒤 처음으로 고점 종가 이상이 된 날짜. `max_dates` 안에 있다 | `null` (미회복 또는 낙폭 없음) | 같음 | 같음 | 없음 |
| `date` | MaxEvent | `String?`, 사건 구간 최저점 날짜. `max_dates` 안에 있다 | `null` (옛 데이터) | 수집기 | 위젯 MAX 잠수 차트 사건 | 없음 |
| `max_closes`·`max_dates` 점 구성 | Quote | 형식·단위 같음. MDD 고점·바닥·회복, 사건 최저점 위치를 점에 더한다(최대 7개) | - | 수집기 | 위젯 | 옛 MAX 가격 선에 점이 최대 7개 늘 뿐 화면 차이 없음 |

- 코틀린: `Quote`에 `max_depths: List<Double> = emptyList()`, `mdd_peak_date: String? = null`, `mdd_trough_date: String? = null`, `mdd_recovery_date: String? = null`. `MaxEvent`에 `date: String? = null`. 모두 기본값이 있어 옛 캐시와 옛 data.json을 읽는다.
- 그대로 두는 것: `max_drawdowns`, `max_events[].index`는 v0.9.0 이하 APK가 낙폭 차트에 쓰므로 수집기가 계속 같은 규칙으로 보낸다. 새 APK는 읽지 않는다(지우는 것은 옛 APK가 사라진 뒤 별도 결정).
- 기존 필드의 형식·단위 변경 없음. 필수 필드 추가·삭제 없음.
- 기기가 덮어쓰는 규칙(`applyLiveQuotes`, 6.5절): `max_depths` 끝 값, `mdd_trough_date`, `mdd_recovery_date`. `mdd_peak_date`와 `max_events`는 덮어쓰지 않는다.
- 추가 티커는 data.json에 들어가지 않는다(기기 `custom.json`에만 있다). 형식은 같은 `Quote`다.
- 크기: `max_depths` 지표당 약 2.5KB × 9 = 약 23KB, 날짜·사건 날짜 약 1KB. 291KB → 약 315KB(+8%) [추정].

## 6. 공유 계산 규칙 (수집기 Python ↔ 기기 Kotlin)

기기 코드는 `model/History.kt`(새 파일)에 순수 함수로 두고, 수집기 함수와 같은 입력에서 같은 결과를 낸다. 아래 고정 기대값은 2026-11-12에 수집기 함수(`drawdowns`, `thin_indices`, `_bucket_size`, `_bar_date_fn`, `big_move_pct`)와 6.2절 의사 코드로 직접 계산했다 [실측].

### 6.1 Yahoo 차트 응답 읽기

| Kotlin 함수 | 수집기 함수 | 규칙 |
| --- | --- | --- |
| `chartCloses(result)` | `chart_closes` | `null` 아닌 종가, 소수 둘째 자리 반올림 |
| `chartDates(result)` | `chart_dates` + `_bar_date_fn` | `null` 아닌 봉의 시장 현지 날짜. `exchangeTimezoneName`을 `ZoneId`로 읽을 수 있으면 봉마다 그 시간대, 아니면 `gmtoffset` |
| `maxStartYear(result)` | `max_fields`의 `max_start` | 첫 봉의 `gmtoffset` 기준 연도 |

- 날짜 고정 기대값: 봉 시각 `1782878400`(2026-07-01 00:00 뉴욕), `gmtoffset=-18000` → 시간대 `America/New_York`이면 `2026-07-01`, 시간대 없음이면 `2026-06-30`, 시간대 `Bad/Zone`이면 `2026-06-30`.
- Kotlin 응답 모델은 지금 `ChartResponse` 계열에 `meta.exchangeTimezoneName`, `meta.instrumentType`을 기본값 `null`로 더해 쓴다.

### 6.2 낙폭, 구간, 점 줄이기

```
drawdownSeries(values):                       # 수집기 drawdowns와 같음
    peak = values[0]
    각 v: peak = max(peak, v); d = (peak > 0) ? max(-100, (v/peak - 1)*100) : 0

drawdownEpisode(values) -> (peak, trough, recovery?, depth)?:
    peak = values[0]; peakIdx = 0; best = 0; trough = null; bestPeak = null
    for i, v:
        if v >= peak: peak = v; peakIdx = i            # 같은 값이면 나중 위치(마지막으로 고점에 닿은 날)
        d = 위 식
        if d < best: best = d; trough = i; bestPeak = peakIdx   # 같은 깊이면 처음 위치
    trough == null 이면 null (낙폭 없음)
    recovery = trough 뒤 처음으로 values[k] >= values[bestPeak]인 k, 없으면 null
    depth = round1(best)

bucketSize(n), thinIndices(values)            # 수집기 _bucket_size, thin_indices와 같음 (MAX_POINTS=500)

maxPicks(values, extras):                     # 새 규칙 (수집기도 같은 함수로 바꾼다)
    picks = thinIndices(values)
    extras(=episode의 peak, trough, recovery와 사건 최저점 위치, null 제외) 중 picks에 없는 것을 정렬 위치에 넣는다
    (thinIndices가 만든 중복은 지금처럼 그대로 둔다)
```

`maxFields`(수집기 `max_fields`) 결과:
- `max_closes` = picks 위치 종가 round2, `max_dates` = picks 위치 날짜
- 낙폭 지표만: `max_depths` = picks 위치의 `drawdownSeries(전체 일봉)` round1, `peak` = round2(최대 종가), `mdd` = round1(최소 낙폭), `mdd_peak_date`·`mdd_trough_date`·`mdd_recovery_date` = episode 위치 날짜
- 수집기만: `max_drawdowns`(지금 규칙 그대로), `max_events`(+`date`)

### 6.4 설정과 화면 정리 (기기만)

- `visibleQuotes(builtIn, custom, settings)`: `order`에 있는 id를 그 순서로, 없는 id는 기본 지표(수집기 순서) → 추가 티커(추가 순서) 순으로 뒤에 붙이고, `hidden`을 뺀다. `order`의 모르는 id는 무시한다. 추가 티커가 캐시에 없으면 `Quote(id, name, price=null, change=null, change_pct=null)`로 채운다.
  - 기본값 + 기본 13개 → 13개, 수집기 순서
  - `order=["GSPC","KS11"]`, `hidden=["VIX"]` → `GSPC, KS11, KQ11, ES, IXIC, NQ, KRW, DXY, TNX, CL, GC, BTC` (12개)
  - 위에 추가 티커 `T:AAPL`(order에 없음) → 끝에 `T:AAPL` (13개)
  - `order=["T:AAPL","XYZ","KS11"]` → `T:AAPL, KS11, 나머지 기본 12개`(XYZ 무시)
- `sanitizeSelection(selection, visibleIds)`: 3.3절 표.
  - `(VIX, null, false)`, VIX 꺼짐 → `(null, null, false)`
  - `(KS11, VIX, false)`, VIX 꺼짐 → `(KS11, null, false)`
  - `(KS11, null, true)`, 모두 보임 → 그대로
- 설정 편집 함수: `moveUp`, `moveDown`, `setHidden`(켜진 것이 1개면 끄기 무시), `addCustom`(8개면 무시, 같은 심볼이면 무시), `removeCustom`(order·hidden에서도 지움), `resetOrder`. 모두 새 `WidgetSettings`를 돌려준다.
- 검색: `hasHangul(q)`, `parseNaverSearch(text)`, `parseYahooSearch(text)`, `mergeCandidates(naver, yahoo)`. 3.2절 표를 그대로 테스트한다.

### 6.5 시세로 덮어쓰기 (`applyLiveQuotes`에 더함)

`depth = drawdownPct(live.price, 새 peak)`가 있을 때(낙폭 지표):
- `max_depths`: 비어 있지 않으면 끝 값을 `round1(depth)`로 바꾼다.
- 새 MDD: `round1(depth) < 옛 mdd`이면 `mdd_trough_date = updatedAt 날짜`, `mdd_recovery_date = null`.
- 회복: `mdd_trough_date != null && mdd_recovery_date == null && live.price >= 옛 peak`이면 `mdd_recovery_date = updatedAt 날짜`.
- 날짜 → 점 위치는 "그 날짜 이하인 마지막 `max_dates` 위치"로 찾으므로, 새 날짜가 `max_dates`에 없어도 마지막 점에 놓인다.

고정 기대값(`max_dates=["2020-01-02","2020-03-02","2026-11-11"]`, `max_closes=[100,70,90]`, `max_depths=[0.0,-30.0,-10.0]`, `peak=100`, `mdd=-30.0`, `mdd_peak_date="2020-01-02"`, `mdd_trough_date="2020-03-02"`, `mdd_recovery_date=null`, `updatedAt="2026-11-12T10:00:00+09:00"`):
- 시세 101 → `max_depths=[0.0,-30.0,0.0]`, `peak=101.0`, `mdd=-30.0`, `mdd_recovery_date="2026-11-12"`
- 시세 65 → `max_depths=[0.0,-30.0,-35.0]`, `mdd=-35.0`, `mdd_trough_date="2026-11-12"`, `mdd_recovery_date=null`
- 시세 95 → `max_depths=[0.0,-30.0,-5.0]`, 나머지 그대로

## 8. 단계와 배포 순서

**결정: 기능 단계는 나누지 않고 v1.0.0 한 번에 배포한다. 작업은 순서 있는 묶음으로 나눠 같은 브랜치에 쌓는다.**
이유: 사용자는 결과를 한 번에 보길 원한다. 묶음 순서(작업 목록 `02_tasks_v1.0.md`)는 공유 계산 함수 → 데이터 → 화면이라 앞 묶음이 테스트로 굳은 뒤 다음이 올라가고, 중간에 CI가 실패해도 원인이 좁다.

배포 순서(계약 규칙: 새 필드는 수집기 먼저):

1. collector-dev·android-dev 작업을 `feature/v1.0-settings`에 올린다. `uv run pytest`, 안드로이드 CI(`gh api -X POST repos/tmfrl132-sys/market-widget/actions/workflows/android.yml/dispatches -f ref=feature/v1.0-settings`) 통과.
2. widget-qa: 새 data.json을 새 코틀린 정의와 v0.9.0 정의로 `check_contract.py` 통과. 옛 APK가 그대로 동작하는지(새 필드 무시, `max_drawdowns` 유지) 확인.
3. `main`을 브랜치 끝으로 fast-forward·push, 수집 수동 실행(`force=true`), Pages data.json에 `max_depths`·`mdd_*_date`·`max_events[].date`가 있는지 확인.
4. 태그 `v1.0.0` push → Releases APK. APK 크기 확인(15MB 이하).
5. 사용자 보고: 설치 방법, 이미 놓인 위젯 크기는 그대로라는 점(3.5절), 설정 화면 여는 법, 태블릿 확인 목록.

수집기를 먼저 올려도 옛 APK(v0.9.0)는 새 필드를 무시하고 화면이 같다. 새 APK가 옛 data.json을 받아도 MAX 잠수 차트는 대체 경로(기기 계산)로 그려진다. 그래서 어느 쪽이 먼저 깔려도 화면이 깨지지 않는다.
