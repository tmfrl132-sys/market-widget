# 경제지표 위젯 설계서

작성일: 2026-10-30

## 목적

갤럭시 탭 같은 안드로이드 태블릿의 홈 화면에서, 한국·미국 주가에 영향을 주는 시세와
다가오는 경제지표 발표 일정을 앱을 열지 않고 한눈에 본다.

### 사용자가 정한 것

- 시장: 한국과 미국 둘 다
- 형태: 안드로이드 홈 화면 위젯 (웹 페이지 아님)
- 내용: 지금 시세 + 다가오는 발표 일정
- 방식: 직접 만든 위젯 앱 (KWGT·웹 위젯 앱 아님)
- 추가 지표: 금, 비트코인
- 등락 색: 한국식 (상승 빨강, 하락 파랑)

### 가정 (틀리면 고칠 것)

- 실시간일 필요는 없고 30분 간격이면 충분하다.
- 위젯은 태블릿 한 대에만 설치한다. Play 스토어 배포는 하지 않는다.

### 성공 기준

1. 태블릿 홈 화면 위젯에 시세 10개와 발표 일정이 보인다.
2. 30분마다 자동으로 새 값으로 바뀌고, 새로고침 버튼으로 바로 바꿀 수도 있다.
3. 한 출처가 실패해도 나머지는 계속 갱신된다.
4. 태블릿에 인증키가 저장되지 않는다.

## 전체 구조

```
GitHub Actions (30분마다)
  └─ collector (Python) ── Yahoo Finance, FRED, 고정 일정표
       └─ data.json ──> GitHub Pages (공개 URL)
                            └─ 태블릿 위젯 앱이 읽어서 표시
GitHub Actions (태그 push 시)
  └─ Android 빌드 ──> APK ──> GitHub Releases ──> 태블릿에 설치
```

저장소: 새 공개 GitHub 저장소 `market-widget`. 무료 GitHub Pages는 공개 저장소가 필요하다.
올라가는 내용은 모두 공개 시세라서 공개해도 문제없다.

## 1. 데이터 수집 (`collector/`)

### 시세 (Yahoo Finance)

| 표시 이름 | 심볼 |
|---|---|
| 코스피 | `^KS11` |
| 코스닥 | `^KQ11` |
| S&P500 | `^GSPC` |
| 나스닥 | `^IXIC` |
| 원/달러 | `KRW=X` |
| 미 10년물 | `^TNX` |
| VIX | `^VIX` |
| WTI | `CL=F` |
| 금 | `GC=F` |
| 비트코인 | `BTC-USD` |

항목마다 현재값, 전일 대비 등락(값·%), 최근 5거래일 종가를 담는다.

### 발표 일정

- 미국 지표: FRED 발표일 API(`fred/release/dates`, 지표별 호출)로 앞으로 14일 안의 CPI, 고용보고서,
  PCE, GDP 발표일을 가져온다. FRED 무료 인증키가 필요하며 GitHub Secrets
  `FRED_API_KEY`에 둔다.
- FOMC·한국은행 금통위: `collector/schedule.json`에 공식 일정을 직접 적는다. 1년에 한 번 갱신한다.

### 실행

- GitHub Actions cron, 30분 간격.
- 한국 시간 토요일 08:00부터 월요일 07:00까지는 건너뛴다. 미국 장이 끝난 뒤라 비트코인만
  바뀌는 시간이어서 갱신할 가치가 작다.
- 결과 `data.json`을 GitHub Pages에 올린다 (`actions/deploy-pages`, 별도 브랜치 없음).

### 실패 처리

- 출처별로 따로 시도한다. 실패한 항목은 직전 `data.json`의 값을 그대로 쓰고 `stale: true`를 붙인다.
- 네트워크 오류는 3번까지 다시 시도한다.
- 오류 메시지에 인증키가 나오지 않게 가린다.

### `data.json` 형식

```json
{
  "updated_at": "2026-10-30T10:30:00+09:00",
  "quotes": [
    {"id": "KS11", "name": "코스피", "price": 2650.12, "change": 12.3,
     "change_pct": 0.47, "history": [2610.0, 2622.5, 2630.1, 2637.8, 2650.12],
     "stale": false}
  ],
  "events": [
    {"date": "2026-11-13", "title": "미국 CPI", "country": "US"}
  ]
}
```

## 2. 위젯 앱 (`android/`)

- Kotlin + Jetpack Glance (안드로이드 공식 위젯 라이브러리).
- 앱 화면은 없거나 최소한(설치 안내 한 장)으로 둔다. 핵심은 위젯이다.

### 화면 (기본 약 4×3칸)

- 위: 시세 타일 10개, 5개씩 두 줄. 타일마다 이름, 현재값, 등락률. 상승 빨강, 하락 파랑.
  `stale`인 항목은 흐리게 표시한다.
- 아래: 다가오는 발표 일정 3~4개 (`11/13(금) 미국 CPI`). 오늘 발표는 강조한다.
- 맨 아래: 마지막 갱신 시각(`10:30 기준`)과 새로고침 버튼.
- 위젯이 작아지면 시세 타일만 보이고 일정은 숨긴다.

### 갱신

- WorkManager로 30분마다 `data.json`을 다시 읽는다. 안드로이드가 허용하는 최소 간격이다.
- 새로고침 버튼은 바로 다시 읽는다.
- 읽기에 실패하면 마지막으로 받은 값을 그대로 보여준다.
- (v0.5.0) 시세는 태블릿이 Yahoo에서 직접 받아 `data.json` 값을 덮어쓴다. 수집 지연을 줄이기 위해서다.
  Yahoo는 인증키가 필요 없어 성공 기준 4를 지킨다. 차트와 일정은 `data.json`에서 받는다.

- (v0.7.0) 코스피·코스닥은 네이버 증권에서 먼저 받는다. Yahoo는 약 20~25분 늦고 전일 일봉이 비는 때가 있다.
  네이버는 비공식 경로라 실패하면 Yahoo로 대신한다. Yahoo에서 전일 봉이 비면 등락률을 비워 둔다.
- (v0.7.0) 화면이 켜져 있으면 자동모드와 상관없이 1분 알람이 마지막 갱신을 보고 5분이 지났으면 새로 받는다.
- (v0.7.0) 타일의 작은 차트는 최근 장 시작부터 받은 시각까지의 5분봉이다. 가로축은 아래 "차트 가로축" 절을 따른다.

### 자동모드 (v0.5.0)

- 머리줄 `자동` 버튼으로 켜고 끈다. 켜면 차트 칸이 첫 종목부터 1분마다 다음 종목으로 넘어간다.
- 끄면 켜기 전 화면으로 돌아간다. 타일을 누르면 그 종목으로 건너뛴다.
- 1분 간격은 기기를 깨우지 않는 AlarmManager 정확 알람으로 만든다. 화면이 꺼져 있으면 멈춘다.
- (v0.6.0) 자동모드 중에는 시세를 5분마다 새로 받는다.

### 낙폭과 전체 기간 (v0.6.0)

- 기간에 오늘(기기가 받는 5분봉, 전일 종가 점선)과 MAX를 더한다.
- 수집기가 `period1=0` 일봉으로 고점·MDD를 계산하고 차트 점은 500개 이하로 줄여 보낸다.
  `range=max`는 간격을 3개월까지 늘리고, 주봉·월봉에는 잘못된 값(원/달러 0.11)이 있어 쓰지 않는다.
- 낙폭은 마이너스 유가 때문에 -100%에서 막는다. 원/달러, 미 10년물, VIX는 낙폭을 만들지 않는다.
- 차트 칸의 고점 대비와 MDD는 고른 기간 기준이다. MAX에서는 가격 아래에 낙폭 차트를 쌓는다.
- (v0.6.1) 전체 기간 차트는 묶음마다 최저·최고를 남겨 고점과 바닥이 사라지지 않게 한다.
- (v0.6.1) 5년·MAX에 로그 눈금을 둔다. 첫 값을 10^0으로 놓고 Y축은 그 배수를 10의 제곱수로 쓴다.
  값이 10배가 안 되면 소수 지수로 나눈다. 0 이하 값이 있으면 일반 눈금으로 그린다.
- (v0.6.1) 낙폭 차트에 주요 사건을 표시한다. 수집기가 사건 구간 안의 가장 깊은 지점을 찾고,
  -15%보다 얕으면 빼며, 지표별로 관련 있는 사건만 붙인다.

### 차트 가로축

눈금과 세로 보조선은 큰 차트뿐이다. (v0.8.0 다음) 시세 타일의 작은 차트도 큰 오늘 차트와 같은 가로 위치(`todayXAxis`)를 써서
장 시작~끝 중 지금까지만 그린다. 눈금 글자, 글자 띠, 세로선, 점선은 그리지 않고 크기, 색, 선 굵기는 그대로다.
장 시간을 믿을 수 없거나 시각이 없으면(옛 캐시, 길이 불일치, 절반 넘게 장 밖) 가로 전체로 늘린다. 점이 1개면 빈 칸이다.

| 필드 | 위치 | 형식·단위 | 빈 값 | 만드는 곳 | 읽는 곳 | 옛 APK 영향 |
| --- | --- | --- | --- | --- | --- | --- |
| `daily_dates` | Quote | `List<String>` `YYYY-MM-DD`, `daily`와 1:1 | `[]` | 수집기 | 위젯 | 없음 |
| `weekly_dates` | Quote | 같은 형식, `weekly`와 1:1 | `[]` | 수집기 | 위젯 | 없음 |
| `max_dates` | Quote | 같은 형식, `max_closes`와 1:1 | `[]` | 수집기 | 위젯 | 없음 |
| `intraday_times` | Quote | `List<Long>` 초 단위 epoch, `intraday`와 1:1 | `[]` | 기기 | 위젯 | 없음 |
| `session_start` | Quote | `Long?` 초 단위 epoch | `null` | 기기 | 위젯 | 없음 |
| `session_end` | Quote | `Long?` 초 단위 epoch | `null` | 기기 | 위젯 | 없음 |

- 1개월~MAX 눈금은 달력 경계에 놓는다. 경계 눈금은 앞 점과 구간이 달라지는 첫 점이고, 인덱스 0은 앞 구간을 알 수 없어
  넣지 않는다. 문구는 실제 그 날짜다(11/1이 일요일이면 코스피는 `11/2`).

| 기간 | 구간 | 문구 | 2026-11-05 코스피 |
| --- | --- | --- | --- |
| 1개월 | 월요일 시작 주 | `M/d` | 10/12 10/19 10/26 11/2 |
| 3개월 | 달 | `M/d` | 9/1 10/1 11/2 |
| 1년 | 분기 | `yy.M` | 26.1 26.4 26.7 26.10 |
| 5년 | 해 | `yyyy` | 2022 2023 2024 2025 2026 |
| MAX | 간격 해의 배수인 해 | `yyyy` | 2000 2005 2010 2015 2020 2025 |

- MAX 간격은 1, 2, 5, 10, 20년 중 눈금이 6개 이하가 되는 가장 작은 값이다.
- 경계 눈금이 2개 미만이면 고르게 5개(첫 점과 마지막 점 포함, 값이 5개 미만이면 값 수만큼, 같은 날짜는 하나만)로 대체한다.
  문구는 1개월·3개월 `M/d`, 1년 `yy.M`, 5년 `yyyy.M`, MAX `yyyy`다.
- 날짜가 정렬되어 있지 않거나 읽을 수 없는 날짜가 있으면 눈금을 만들지 않는다.
- 날짜와 값의 길이는 기간별로 자르기 전에 비교한다. 다르면 눈금 없이 지금처럼 그린다.
- 기기 시세로 일봉이 1개 늘면 `updated_at` 앞 10글자를 `daily_dates` 끝에 붙여 길이를 맞춘다.
- MAX에서 낙폭 차트를 쌓으면 낙폭 차트에 세로 보조선과 글자를, 가격 차트에 세로 보조선만 그린다. `max_drawdowns`는 묶음마다 1점이라
  `max_dates`와 개수가 다르지만 같은 기간을 덮으므로, `max_closes` 기준 눈금을 가로 비율 그대로 쓴다.
- 오늘: 가로 위치 = (봉 시각 - 시작) / (끝 - 시작), 0~1로 제한한다. 영역 채우기와 끝 점은 마지막 봉까지이고,
  세로축과 전일 점선은 가로 전체를 쓴다.
- 장 시간은 Yahoo `meta.tradingPeriods`에서 첫 start와 마지막 end를 읽는다. `currentTradingPeriod`는
  미국 지수에서 다음 거래일을 가리켜 쓰지 않는다. 다른 형태이거나 없으면 장 시간을 모르는 것으로 처리한다.
- 네이버는 그 날짜 09:00~15:30 서울 시간으로 둔다. 마지막 봉이 15:35보다 늦으면 끝을 마지막 봉까지 늘리고,
  15:32 같은 동시호가 봉은 오른쪽 끝에 붙인다.
- 시각 길이가 값과 다르거나, 시작·끝이 없거나, 끝이 시작 이하이거나, 봉의 절반을 넘게 시작~끝 밖이면 가로 전체에 늘려 그리고
  눈금을 없앤다. 정확히 절반이면 믿고, 소수만 밖이면 끝에 붙인다.
- 오늘 눈금: 시작과 끝 사이에 서울 시간 정시를 넣는다. 간격은 1, 2, 3, 4, 6시간 중 시작·끝을 합쳐 8개 이하가 되는
  가장 작은 값이고, 시작이나 끝과 가로 위치 차이가 0.08 미만인 정시는 뺀다. 문구는 `HH:mm`이다.
- 오늘 봉을 받지 못하면 `intraday`, `intraday_times`, `session_start`, `session_end`를 함께 유지한다.
- 그리기: 그림 아래쪽에 글자 띠를 잡고 세로 계산은 그 안에서 한다. 글자는 눈금 가운데에 놓되 그림 영역 가로 범위 안으로
  밀어 넣는다. 겹치면 앞 눈금부터 건너뛰되 마지막 글자는 건너뛰지 않는다.
- 세로 보조선: 눈금 위치에 가로 눈금선과 같은 색과 굵기로, 선과 영역보다 먼저, 글자 띠 위까지만 그린다.
  글자를 건너뛴 눈금에는 그리지 않는다.

### 배포

- 태그(`v*`)를 push하면 GitHub Actions가 APK를 빌드해 Releases에 올린다.
- 사용자는 태블릿에서 APK를 받아 설치한다. 처음 한 번 "출처를 알 수 없는 앱 허용"이 필요하다.

## 3. 테스트

- collector: pytest. 외부 접속은 가짜 응답으로 바꿔서 검사한다. 실패 시 직전 값 유지와
  `stale` 표시, 일정 필터링(14일 이내)을 검사한다.
- 위젯: `data.json` 해석과 날짜 표시 형식을 JVM 단위 테스트로 검사한다.
- 실제 위젯 화면은 태블릿에 설치한 뒤 사용자가 확인한다.

## 4. 먼저 확인할 위험

- 네이버가 GitHub Actions 접속을 막았던 것처럼 Yahoo도 막을 수 있다. 구현 첫 단계에서
  GitHub Actions로 Yahoo·FRED 접속을 시험한다. 막히면 다른 출처를 찾고 이 설계서를 고친다.

## 하지 않는 것

- 실시간 시세, 알림, 종목별 시세, 여러 기기 동기화, Play 스토어 배포.
